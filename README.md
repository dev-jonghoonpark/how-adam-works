# how-adam-works

Adam 옵티마이저는 어떻게 동작하는가 — **파라미터마다 따로 재는 보폭**. 다섯 줄짜리 알고리즘의 각 줄이 왜 있는지를 — 이동 평균의 기억 길이, 편향 보정, √v로 나누기, 신호 대 잡음비, 희소한 기울기, weight decay의 위치, 수렴 반례, 메모리 비용 — 브라우저에서 직접 계산해 보는 인터랙티브 교육 자료입니다.

## 한 문단 요약

SGD는 모든 파라미터에 같은 학습률을 곱합니다. Adam은 파라미터마다 **최근 기울기의 평균(m, 약 10스텝)**을 **최근 기울기 제곱 평균의 제곱근(√v, 약 1000스텝)**으로 나눈 만큼 움직입니다. 기울기가 꾸준하면 이 비율은 sign(g)가 되어 한 스텝 거리가 **≈ α** — 학습률이 "기울기에 곱하는 수"에서 "거리"로 바뀌고, 손실을 10배로 키워도 궤적이 전혀 변하지 않습니다. 기울기가 흔들리면 비율이 `μ/√(μ²+σ²)`로 줄어 **확신이 없을 때 알아서 작게 움직이고**, 드물게 기울기를 받는 파라미터는 v도 작아 SGD의 1/p 대신 **1/√p**로 배웁니다(p = 50에서 2% → 14%). 0에서 시작한 m, v를 되돌리는 **편향 보정**을 빼면 기본값에서 초반 스텝이 **최대 6.57배(t = 12)**로 튑니다. 한계도 있습니다 — √v는 좌표축마다 따로 재는 값이라 **비스듬한 골짜기는 보정하지 못하고**, L2 정규화를 기울기에 넣으면 decay까지 √v로 나뉘어 파라미터마다 강도가 달라지므로(데모에서 **201배** 차이) **AdamW**처럼 따로 넣어야 하며, **Reddi 외(2018)의 반례**에서는 최적해의 정반대로 수렴합니다. 그리고 파라미터마다 숫자 두 개를 더 들고 있어야 해서, 7B 모델 학습에 필요한 112 GB 중 절반이 m과 v입니다.

## 이 페이지가 답하는 질문

- Adam의 학습률 1e-3은 무엇의 1e-3인가? (기울기에 곱하는 수가 아니라 한 스텝에 움직이는 대략의 거리)
- 편향 보정은 왜 필요한가? m의 편향만 있으면 스텝이 작아질 텐데? (v의 편향이 더 오래 남아 오히려 스텝이 커진다)
- Adam은 SGD보다 항상 빠른가? (아니다 — 잘 맞춘 Momentum이 더 빠를 수 있다. 장점은 튜닝 없이 안 망가지는 것)
- Adam은 왜 최솟값 근처에서 저절로 조심스러워지는가? (신호 대 잡음비가 떨어지면 m̂/√v̂가 작아진다)
- 임베딩에 Adam이 잘 듣는 이유는? (드문 파라미터일수록 v가 작아 한 번 받을 때 크게 움직인다)
- `Adam(weight_decay=…)`과 `AdamW`는 같은가? (아니다 — 전자는 L2이고 decay가 √v로 나뉜다)
- Adam은 볼록 문제에서 항상 수렴하는가? (아니다 — Reddi 외 2018)
- 7B 모델을 학습하려면 GPU 메모리가 얼마나 필요한가? (활성값을 빼고 112 GB, 그중 m·v가 56 GB)

## 숫자에 대하여

페이지의 모든 수치 — 이동 평균, 보정 배율, 경주 궤적과 도달 스텝, 스텝/α 평균, 희소 비율, weight decay 곡선, 반례의 최종 x, 메모리 — 는 브라우저 안에서 실제로 돌린 결과이며 하드코딩된 값이 아닙니다. 노이즈는 고정 시드로 생성되므로 새로고침해도 같은 결과가 나옵니다.

데모들은 모두 **장난감 문제**입니다. §4의 경주는 결정적(노이즈 없는) 2차 함수라 Adam에게 가장 불리한 무대이고, §7은 "평균 0인 기울기"를 매 스텝 부호가 바뀌는 ±σ로 단순화했습니다. §8의 반례는 논문의 온라인 볼록 최적화 설정(β₁ = 0, 학습률 α/√t, [−1, 1]로 사영)을 그대로 따랐습니다. §9의 메모리는 파라미터에 비례하는 상태만 세고 활성값·임시 버퍼·단편화는 넣지 않았습니다.
